## Bottom line

The overlap is substantial in the visible toolkit: named liquidity, sweeps, iFVGs, HTF FVG context, SMT, signal tooltips, a checklist, and risk-plan drawings. SNM+ already has those building blocks, but it arranges them around the user's D/T/E rulebook and C/RB/RV setup semantics. The clearest product-level differences are V9's independently switchable signal/zone visibility, its recent-only presentation, separate visual liquidity detectors and event-alert categories, a fuller always-visible checklist, and its 8AM/9AM range inputs.

The biggest semantic trap is **LRL/HRL**. The same labels refer to materially different constructions in the V9 narration, SNM+'s current calculations, and the ICT corpus. They should not be copied or promoted into SNM+ gates by name alone. Most of V9's optional filters should likewise not become new SNM+ vetoes: several overlap checks that already affect SNM+'s grade or rulebook.

## What looks most useful to borrow as design—not as rules

1. **Independent presentation controls.** V9 makes “show signals,” “show iFVGs,” and recent-only drawing choices easy to find. SNM+ already separates HTF-gap drawing from gap calculation, but it has no one-to-one display-only “hide qualified setup tags” control: `Show setups from grade` is an eligibility/display floor, not just a visibility switch. If added, a visibility control should hide drawings only, leaving calculation, grade, records and alerts untouched. An optional recent-only view should likewise be visual-only.
2. **A more glanceable checklist.** V9's compact table can make the current state legible without hovering. SNM+ already has the status line, D/T/E panel, detailed setup tooltip and optional Now row, so any expansion should reuse existing checks, be opt-in, remain token/object-budget conscious, and never add a gate or change what the current grade means.
3. **Explicitly defined 8AM/9AM ranges.** These may be useful named levels, but the transcript/screenshots do not establish a complete mechanical definition. First agree the range interval, NY-time/DST treatment, when its H/L locks, whether it stays projected until swept, and whether it feeds active liquidity or is display-only. Keep the existing session pool and rulebook windows separate.
4. **Separate event alerts.** This can be an opt-in alert layer for confirmed level/SMT events without changing setup alerts. Define the event (wick, close, divergence resolution, etc.) and deduplication before coding; replay labels alone will not verify TradingView alert delivery.

These are candidates only—not a request to implement them now. If a later feature changes inputs, update `snm-plus-guide.md` and `snm-settings-by-pair.md` with that same code change. Any setting that changes eligibility or grading should default to preserving current SNM+ behavior unless the user explicitly chooses otherwise; display-only controls should not force manual timeframe retuning.

## Decision

**Keep SNM+ 3.63's current setup, grade, alert, session and LRL/HRL semantics. Do not port V9 code or claims.** Treat the optional visible checklist, recent-only display, precisely defined 8AM/9AM CR levels, and standalone event alerts as separate, opt-in proposals.
