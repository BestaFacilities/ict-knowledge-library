## Limits and adoption risks

- **VShapeS+:** its V-shape eligibility and target grade measure a different event than SNM+'s confirmed sweep/CISD setups. An incomplete marker is informative, not a confirmed signal. Separate signal/alert timeframe controls can multiply confusing switches; if ever needed, derive auto defaults from chart TF and provide one opt-out.
- **2022 Model Pro+:** synthetic fallback targets can make missing market structure look like a valid trade plan. Forcing a minimum one contract when calculated size is zero breaks a risk budget. SNM+ should continue to show a non-tradable size rather than silently round up.
- **ICT Setup Builder:** a macro/session dashboard and skipped-reason ledger can add information but also substantial visual, input and runtime complexity. A skip reason must reflect the existing SNM+ rule, not quietly become a new filter.
- **FRACTAL ULTRA PRO:** a multi-symbol fractal/session engine and pooled drawing objects add complexity and resource pressure. Read-only stage labels are safer than adopting its state machine as another entry engine. Source alone does not establish its historical/realtime equivalence.
- Across all four, source code alone does not establish TradingView compilation, market-data behavior, correct timezone/feeds, or an independently tested win rate. Avoid silently changing SNM+'s sweep/CISD eligibility, SMT pair selection, HTF gap invalidation, stops, sizing, grade, or B-alert policy.
